Entrega multi-dispositivo

Tres dispositivos confirman a la vez, con reintentos. ¿Cómo se cuenta el progreso sin contar de más?

Un mensaje va a tres dispositivos. Cada uno confirma cuando lo recibe — y como la red falla, cada uno confirma varias veces. Algunos llegan fuera de orden: un "lo recibí" que aparece después de un "lo leí".

El sistema tiene que saber cuándo terminó de entregar, para liberar el trabajo pendiente. Si cuenta mal, pasa una de dos cosas: libera antes de tiempo y alguien nunca recibe el mensaje, o no libera nunca y el trabajo se acumula para siempre.

El error de fondo es sutil: contar eventos en vez de contar cambios de estado. Veinte confirmaciones del mismo dispositivo son veinte eventos y un solo cambio.

Dónde está la diferencia

Sin protección

-- llega una confirmación
INSERT INTO receipts (device_id, state)
VALUES ($1, $2);   -- una fila por evento

UPDATE batches
   SET delivered_count = delivered_count + 1
 WHERE message_id = $1;

-- suma por ACK recibido

Con protección

UPDATE delivery_receipts
   SET state = $3, version = version + 1
 WHERE message_id = $1 AND device_id = $2
   AND array_position(estados, state)
     < array_position(estados, $3);

-- ¿actualizó 0 filas? era duplicado.
-- sólo si cruzó el umbral por PRIMERA vez:
UPDATE batches SET delivered_count + 1;

CHECK (delivered_count <= expected_count)

La comparación de estados vive en el WHERE, no en TypeScript. Un "lo recibí" que llega después de un "lo leí" actualiza 0 filas — y eso no es un error, es la respuesta correcta.

El progreso se suma únicamente cuando el recibo cruza el umbral por primera vez, en la misma transacción que ese cambio. Veinte confirmaciones mueven el recibo una vez, así que suman una vez.

Y el CHECK del schema es la red debajo: si algún día un bug sumara de más, la base grita con un error en vez de dejar que el trabajo se libere antes de tiempo.

Son tablas distintas porque tienen vidas distintas. El trabajo pendiente se borra cuando todos confirmaron; la evidencia no se borra nunca. Si el estado de entrega viviera en el trabajo, la limpieza habría borrado justo lo que hace falta para auditar que la limpieza estuvo bien.
