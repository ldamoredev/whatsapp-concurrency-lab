Tres procesos, una sola verdad

¿Qué impide que dos réplicas creen el mismo mensaje dos veces?

Este laboratorio corre tres réplicas de una API de mensajería, con memorias separadas y una sola base de datos. Cada escenario provoca una carrera de verdad: los requests salen de tu navegador hacia las tres.

Lo que hace distinto a este panel es que cada escenario se ejecuta dos veces. Primero por el camino ingenuo —el código que uno escribe cuando todavía no pensó en concurrencia, que se lee razonable y pasa el code review— y después por el camino real del sistema. Misma entrada, misma base, resultados incomparables.

Una constraint no se entiende por lo que permite. Se entiende por el desastre que impide.

Lo que este laboratorio no demuestra

PostgreSQL corre con una sola instancia: esto prueba consistencia de aplicación, no alta disponibilidad de la base ni tolerancia de zona. Todavía no hay Kubernetes, ni carga sostenida medida, ni inyección de fallos de red.

Tampoco hay balanceador: cada réplica expone su propio puerto y el reparto lo hace esta página. Con Traefik eso deja de hacer falta.

Escenarios y estado se apoyan en consultas contra la base, no en respuestas HTTP. Contar 2xx no demostraría ninguna de estas propiedades. El botón reiniciar de cada escenario trunca las tablas: es la funcionalidad, no un riesgo. Se apaga con LAB_PANEL_ENABLED=false.
